Save State when a deploy is stopped. `deploy()`, `provision()` and `publish()` accept a `signal: AbortSignal`. When it aborts, no new Operation starts, requests in flight get 5 s to finish and are then aborted, and the run writes State with the creates that finished and releases the lock. A new optional `interruptGraceEnd: AbortSignal` ends that 5 s wait at once when it aborts. The CLI aborts the signal on the first SIGINT or SIGTERM, ends the 5 s wait at once on a second one, and exits with code 130 or 143. When a `.bedrock/<command>.ts` override runs, the CLI sends each SIGINT and SIGTERM on to the override process and exits as that process does. A `.bedrock/build.ts` child also gets each signal; a custom `Spawner` gets the signals through the new optional `SpawnInvocation.signals`. Each game pass, developer product and badge create request now times out after 120 s and goes to create recovery. No paid badge create is sent after the Interrupt begins, even one that was being prepared; a Driver reads the new optional `ResourceApplyContext.stop` for this. A paid badge create that was aborted or timed out is recorded as an Unconfirmed paid create. A new `interrupted` `ApplyError` names each Operation that did not start.
